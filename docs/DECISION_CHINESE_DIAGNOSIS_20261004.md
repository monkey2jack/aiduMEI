# f0.3++：排名变化原因与中文核验专项（2026-10-04）

当前证据没有显示 Drex 的能力隔夜下降。昨日与今日测试的数据、提示与评分口径不同；今日评分还暴露了字面锚点误罚。补充的中文专项中，Jev答对64/64、Clef62/64、Drex与Flash各61/64，差距仅2—3题，不足以宣布综合冠军。更明确的发现是：Drex对混杂长记忆的证据判断存在可重复的回归，Clef两款也会把相关对象的层级描述误当成查询对象的具体层级。

这是本地模型调用与回执分析，尚未部署生产。测量对象是候选是否直接给出答案，不是LLM最终回答准确率，也不涵盖记忆提取、六类分类、embedding或索引的综合优劣。

## 一、为什么昨天 Drex 表现稳，今天评分却落后

| 因素 | 昨日实验 | 今日实验 | 可以推断的范围 |
|---|---|---|---|
| 比较对象 | 无决策 vs Drex | 无决策、Drex、Jev、Clef、Flash | 昨日不能建立Drex相对另外三个模型的排名 |
| HTTP题目 | 50题合成记忆，12个家族 | 60题真实历史库，18个事实家族与无答案题 | 90%/98%与43.33%—53.33%不属于同一任务分布 |
| 历史/上下文 | 简短、清晰的事实与诊断回放 | 长原文、版本更新、别名、混合主题及多次状态变更 | 真实库对限定条件、主体与时间理解要求更高 |
| 分类提示 | 早期组件使用中文指令与较详细类型定义 | 产品使用英文指令与简短中文类型标签 | 提示和定义不同是混杂因素；尚未单独证明哪个因素造成差距 |
| 评分 | 固定答案内容 | 要求同条结果包含全部字面锚点 | 正确的简短等义答案可能被扣错 |
| 代码候选 | `8df0174b949c310d9e1feb1f3057ec06a72ecc30` | `b9c91d0448865be673013bd706f8d48b6234c21e` | 各自内部A/B可比较，跨实验不能归因于模型本身变化 |
| 缓存/执行 | 有成功缓存命中及自动跳过 | 每题清理成功缓存并轮换模型顺序 | 缓存、候选数量和跨阶段调用次数影响耗时 |
| 决策支持门槛 | 0.6 | 0.6 | 数值相同，但不同模型概率未必处于同一校准尺度 |

今日 Drex 出现的一次 ReadTimeout 所在题，不属于其三道“基线通过、Drex评分失败”题，不能用该超时解释这三题。没有保留昨日三模型在相同固定输入上的原始回执，无法证明供应商升级模型或服务波动导致了排名变化；接口当前严格核对请求与响应模型版本，也不等于内部服务实现绝对不变。

对今日回执的后验复核已更正[原报告](DECISION_EVALUATION_20261004.md)：一题返回正确的60张但缺少变量名；CF的一题保留嵌入式建议但缺少字面“数据量小”；图库“当时”的题缺少时间限定。保留冻结的原始分数，撤回把所有评分下降称为误拒的解释。未盲法复核全部60题，不生成选择性修正后的总体准确率。

## 二、中文专项协议

- 32个合成查询家族，每个家族一条可回答候选和一条缺少答案的候选，形成64个中文判断；每条配人工同义英译，共64个英译判断。中英不是128个独立家族，正负候选也共享查询。
- 八类各8题、正负各4题：否定与双重否定、指代/对象归属、时间更新、明确别名、中文口语、数值/单位/农历、提议与正式决定、仅提及主题或测试报告声称命中。
- 模型及版本：`drex-v1.5`、`jev-1.13.0`、`clef`、`clef-flash`；共512次真实接口调用，全部有效响应，没有错误或重试。
- 每次仅含一条候选。四个模型使用相同state结构、产品适配器和中文核验提示；英译组也保留同一中文提示，以避免把提示变化混入正文语言对照。此设计测试同一中文核验器处理两种语言，不是通用中英能力榜单。
- Gold与协议在外呼前落盘并冻结，支持阈值0.6；无LLM回退、无产品决策缓存，并发2，轮换模型和语言顺序。单次读取超时5000ms用于观察完整响应，区别于产品2000ms；超出2000ms数量单独记账。
- “明确的否定答案”也算提供答案；“尚未核实”“尚无结论”“只有提议”不能替代查询所需的已确认状态/属性。不把与问题立场一致当成唯一正确条件。
- 无决策组件对照是保留所有输入候选：保留32/32正例，但也放行32/32负例，即32/64正确、增加决策耗时为0。**这不是既有reranker或完整HTTP检索系统的50%准确率**；完整HTTP关闭决策基线仍见原报告。
- 本轮测量使用合成题目，未公开生产原文、身份或凭据。公开面复核发现合成题中的地点仍沿用了内部称呼，原始题目与冻结协议已转为私有保存；公开文件只保留协议元数据与逐题编号。原始协议hash为 `1475bb53eadf1386dfcf1f1bb1703884692d0b0ea85774305fc0ef38836fa1ae`，历史聚合结果保持不变。公开脚本现使用虚构节点的v2题集，中英同步替换；该题集尚未重新实测，不能承接本报告分数。

在这组重复输入上，错误可重复，短时间内没有观察到判定漂移；不支持“今天恰好网络不好或模型随机发挥”作为主要解释。此结果不提供跨天稳定性、压力或长期可用性的证据。

## 五、Drex长上下文的原因定位

从真实HTTP回执选取一条包含明确层级要求的记忆，比较同一查询、同一模型、同一提示下的完整记忆与关键原句。完整文本3237字符，关键句37字符。再加入关于另一个对象位于下方、未指明查询对象具体层级的负例，每组重复两次；共24次调用。完整文本与逐题回执留在私有目录，公开文件仅含字数和聚合概率。

| 输入 | 正确判定 | Drex支持概率 | Jev支持概率 | Clef支持概率 | Flash支持概率 |
|---|---|---:|---:|---:|---:|
| 完整长记忆，包含直接答案 | 保留 | 0.0463 / 0.0463 | 0.82 / 0.81 | 0.9645 / 0.9645 | 0.9221 / 0.9221 |
| 同记忆的关键原句 | 保留 | 0.9891 / 0.9891 | 0.86 / 0.87 | 0.9590 / 0.9590 | 0.9303 / 0.9303 |
| 仅描述另一个对象的相对层级 | 拒绝 | 0.6326 / 0.6326 | 0.32 / 0.32 | 0.7619 / 0.7619 | 0.6471 / 0.6471 |

按0.6门槛，Drex在长正例上2/2误拒，而关键句2/2正确；Jev在三类输入均正确；Clef、Flash保住长正例，但也2/2放行对象不符的负例。Drex在稍改措辞的负例上也2/2放行，显示不能以首轮较短题全部正确来代替稳健性验证。

这次消融证明输入组织方式能显著改变该Drex实例的判断，支持长记忆中混杂内容干扰证据归属的诊断。它同时改变了文本长度与内容混杂度，**不能单独归因于字符长度、位置或中文本身**。只有一条真实记忆、两次重复，也不能概括全部长文本。无需把Drex阈值一路降到0.04：主体错误负例本来就高于0.6，这样降阈值会放行更多错误。

## 六、对 f0.3++ 的设计与部署影响

1. **证据输入组织优先。** 为长记忆构造带来源偏移的证据窗口，保留查询主体、指代的先行词、否定、时间和修正句。核验窗口不改写原文，也不删除历史。抽出“最顶层”而漏掉主体/取消/新状态会造成新错误，必须有对照验证；目前尚未修改生产检索代码。
2. **分开判断答案存在与答案归属。** 直接答案是否存在、主体是否一致、时间是否符合、状态是否已确认分别输出并记遥测。试验这是否比一个混合支持概率更可靠，同时统计额外调用开销。关系词“上方/下方”不能冒充确定的最顶/最底层答案。
3. **按模型、任务校准概率。** 分类0.7和证据0.6不是跨厂商可靠度的统一刻度。用独立校准/留出集选择门槛，分别关注正例保留和负例拒绝；保留缺失分/异常的既有回退。不得在本次分歧题上调门槛后把分数当作泛化收益。
4. **修正评估数据与判据。** 时间明确，答案按主体/属性/值及来源匹配，允许等义短句；字面锚点只作为可追踪诊断。先做匿名、独立语义复核，再冻结新的真实库留出集，不选择性删难题。检查索引覆盖，核验器无法找回上游已漏掉的候选。
5. **任务可选、供应商可换、reranker保留。** 目前Jev值得优先进入检索核验留出验证，Drex保留为速度相近的候选并重点修长文本输入，Clef/Flash继续验证对象条件与分类回退；没有证据支持全任务强制迁移。分类的原始choice与LLM回退结果另报，不能拿本次二分类专项替代六类分类结论。
6. **封版前补真实留出与运行预算。** 对新窗口方案与原方案，在相同生产副本、无决策基线、固定reranker下比较；同时记累计核验预算、p50/p95、误保留/误拒与分类回退率。已有5000ms专项成功不能替代2000ms产品预算验证。部署前仍按维护者要求停下汇报。

## 关于跑分：我们的态度

**2026-09-22 我们跑了第一次，成绩不好看，我们照样公布——连错题本一起。**

这一页此前写的是「本版没有跑分，所以不宣称任何分数」。那句话现在过期了，于是整页重写：
**说过的话到期就要兑现，不能让一份过期的承诺继续挂在那儿装门面。**

### 我们跑出了什么

首次 LoCoMo 试跑（2 样本 / 304 题 / F1 口径）：总分 **F1 42.14%**、LLM-Judge 52.96%。
分维度对比表、复现条件与逐条解读都在 [README](../README.md#-跑分我们跑了连错题本一起交)，不在这里重复。

一句话概括：**单跳直接召回进第一梯队、防幻觉断层领先、时序推理是明确短板、开放域数据量不够不作数。**

### 我们坚持的三件事

- **连复现方法一起交。** 评测协议冻结在 `benchmarks/`：数据集、模型、judge、prompt、seed、文件哈希全部锁定留证，
  适配器走真实 HTTP 契约。我们公布分数的那一天，你拿同一份协议应该能跑出同一个数 ——
  **这才是我们认为分数唯一有意义的形态。**
- **口径必须随数字一起走。** 记忆基准有两把不可混用的尺子：**F1**（逐词重叠，严）与
  **LLM-Judge**（语义等价，宽）。业内宣传的「LoCoMo 90%+」几乎都是 Judge 口径且经方法迭代。
  拿它跟别人的 F1 比是关公战秦琼，会把差距凭空夸大数倍 —— 我们自己在分析这次试跑时就先踩过一次这个坑，
  所以现在任何对外引用都必须同时标注**口径 + 样本量 + 裁判模型**，缺一不可比。
- **不拿试跑冒充定稿。** 这次是 2/10 样本、裁判是 Sonnet 而非业内口径的 GPT-4o。
  它够用来定位问题，**不够用来对外宣称成绩**，更不够用来说 SOTA。正式打榜须全量 10 样本 + GPT-4o 裁判复跑。

### 第一次跑分的价值是暴露问题，不是拿分数

这句话我们在跑之前就写在这页上了，跑完发现它比预想的还准：

这次试跑直接炸出一个藏了很久的根因 —— **写入时把「事情发生的时间」悄悄换成了「记录存进来的时间」**，
不报错、不告警，检索照常返回、健康检查照常全绿。时序题 39% 的证据条目带着错误的时间进了答题上下文。
一个漂亮数字换不来这个发现。

同类的「看着能用、实际空转」我们在开发中反复见过：推理模型在 token 上限下每题返回空、成绩单却报 0 错误；
嵌入维度参数出厂就带着错的发货。所以第一次的数明显低于第二次 —— **那正是它该有的样子。**

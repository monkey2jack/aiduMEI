# 三态纪律（v22.0 · 雷霆审计 D2）

> 雷霆审计 DeepSeek AUD-16：本项目最有价值的对外资产之一。

## 规范

**任何判据必须能表达第三种状态「无法判断」，且「无法判断」默认不得等价于「通过」。**
需要放行时必须显式 SKIP 并计入总结。

三态语义：

| 状态 | 含义 | 退出码/表现 |
|---|---|---|
| 通过 | 判据成立 | `0` / `ok: True` |
| 失败 | 判据不成立 | `非 0` / `ok: False` / `degraded` |
| **无法判断** | 样本不足 / 探针未鉴权 / 环境缺件 | **`2` 或显式 SKIP，不得报 `ok: True`** |

## 施工纪律

- 新增探针/判据时先问：「它的『无法判断』长什么样？」
- 不能三态化的判据不许进 `/health`——「不知道」不是「健康」。
- 守卫测试必须带负向对照：改坏判据必须让测试红。

## 为什么这条比功能卖点更难被抄袭

功能可以抄，但「把『不知道』和『通过』分开」是工程文化——它要求每个写守卫的人
先想清楚自己的守卫会怎么骗自己。本仓的台账文化（SECURITY-AUDIT-LEDGER）与
这条纪律同源：不掩饰失败，但也不把「没测」说成「通过」。
